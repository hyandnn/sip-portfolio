# Sipfolio

把喝过的酒瓶变成贴纸，收进自己的数字收藏册。

Sipfolio 是面向个人使用的酒类收藏应用，覆盖多种酒类。核心流程是：导入酒瓶照片 → 抠出主体 → 预览贴纸 → 填写信息 → 保存到收藏墙 → 查看详情。

## 项目背景

- 用户已选定名称 **Sipfolio**。
- 用户喜欢宝可梦，选择现代、活泼、多彩的卡片与图鉴收集感。
- 原始愿景还包括酒款介绍、风味和鸡尾酒建议，可以分阶段加入。
- 共享对话最后的交接摘要记录了首版范围：先 Mac、每款酒一个条目、名称＋类别＋备注。

完整背景、范围与开发顺序见 [项目交接说明](docs/PROJECT_HANDOFF.md)。

## Mac 版（0.6.0）

已实现：

- 导入或拖入酒瓶照片，支持 JPEG、PNG、HEIC 等系统可读取格式。
- Vision 前景抠图、透明 PNG、白色贴纸描边；检测到多个主体时可手动选择。
- 原图／贴纸预览、重新抠图、换照片和原图收藏回退。
- 酒名、类别、口味、年份、备注，以及可调的收藏日期。
- 按「酒名＋口味＋年份」检查重复，允许同名的不同口味／年份分别收藏。
- 收藏墙、类别筛选、酒名／备注搜索与排序。
- 收藏详情、信息编辑、确认删除，以及导出贴纸 PNG。
- SwiftData 本地持久化，原图、贴纸和缩略图分别保存。
- DeepSeek 图片识别：生成酒名、类别、简介、风味与鸡尾酒建议，核对后采用。
- 为已有收藏补充 AI 酒款资料，重启后仍可查看。
- AI 设置、钥匙串保存密钥与连接检查。
- 自由输入酒类，输入时提示已有收藏中使用过的类别；保留 AI 返回的蜂蜜酒等自定义类别。
- 独立鸡尾酒集，保存、查看、编辑、搜索与删除配方，记录材料用量、步骤、杯型、装饰和备注。
- 从酒瓶推荐喝法创建配方，可用 DeepSeek 生成调配建议，检查修改后保存。
- 白底薄荷绿像素酒瓶笑脸图标 v2；收藏页、导入、详情、配方、AI 建议和设置采用统一像素字体、阶梯边框与方块按钮。
- 「藏酒屋」和「蒙汗药」两个入口；顶部只保留英文与 slogan，排序菜单直接显示三个纯文字选项。
- 保存酒瓶时默认收录已确认的 AI 推荐喝法，可取消勾选；同名喝法合并并关联多个酒瓶。
- 联网查找匹配的公开鸡尾酒配方和成品原图，保存完整背景与来源；可导入自己的照片，卡片图框统一尺寸。

0.1.1 修正：左上角品牌名使用 `Sipfolio`；新建和编辑表单的类别选择器统一为单个右侧箭头；收藏卡片中的贴纸居中显示。

0.2.0 已加入 DeepSeek 在线图片识别，不要求先接入 OCR。采用建议前可以编辑酒名与类别；AI 不会自动写入收藏，也不会发送个人备注。

0.3.0 新增口味与年份手动字段。口味用于区分经典、佛手柑等版本，可留空；年份为可留空的文本，不必加在酒名里。新增和编辑收藏时都能选择收藏日期，例如购买或收到这瓶酒的日期。收藏墙按这个日期排序，并显示年份。

「口味」与「风味」分开：卡片名称下方展示手动口味／年份；类别后展示最多两个 AI 风味标签，悬停可查看全部。没有风味资料时不生成标签；可以从详情页补充 AI 资料。

0.4.0 移除类别下拉表单和 AI 固定类别映射。类别可以填写任意名称，空值保存为「未分类」；侧栏按实际收藏生成类别，不预置空类别。输入框聚焦时显示匹配的历史类别，点击即可采用。

鸡尾酒集与酒瓶集在左侧切换。酒瓶详情「可以试试」的推荐项旁点 ＋，打开配方编辑页；点「AI 生成调配建议」，检查材料、用量和步骤，再点「加入鸡尾酒集」。也可在鸡尾酒集中点「新配方」手动记录。AI 不自动保存、不自动覆盖已有配方内容；重新生成有内容的配方时先确认替换。关联酒瓶名称按创建时保留，删除酒瓶不会删除配方。

0.5.0 按用户命名改为「藏酒册／蒙汗药」。在新酒瓶导入页采用 AI 建议后，「同时收录推荐喝法」默认勾选，保存酒瓶时把推荐条目一起收进蒙汗药。这里只保存已确认的推荐名，材料和步骤随后由联网查找补充，尚未找到时标记待补充。手动新建配方入口仍保留。

在蒙汗药点「收录酒瓶推荐」，可一次收录已有酒瓶保存过的推荐；相同喝法按常见中英文名称合并，已有材料、步骤与备注继续保留，关联酒瓶名称均可搜索。不同的明确变体，例如 Negroni 与 Negroni Sbagliato，不合并。

公开配方与成品图通过 [TheCocktailDB 官方 API](https://www.thecocktaildb.com/api.php) 获取，联网只发送鸡尾酒／喝法名称，不发送个人备注、照片或酒瓶收藏。配方严格按名称匹配，保留来源的用量；优先使用来源提供的中文步骤。图片使用官方接口返回的本站 HTTPS 成品地址，详情保存署名、配方页与原始来源链接，元数据如实保存 Creative Commons 确认状态，不把未确认图片标为 CC。成品图为该喝法的示意，可能与自己的配方版本不同。当前按照官网链接的[使用条款](https://www.thecocktaildb.com/terms_of_use.php)使用开发项目的 API 数据与图片，公开商店分发前需按其文档配置生产访问。

0.5.1 将「藏酒册」改名为「藏酒屋」，两页顶部移除重复的中文收藏册标题，保留英文和一行 slogan。排序菜单取消选中对号，三个选项文字统一对齐，当前排序仍显示在菜单按钮上。

蒙汗药的成品照片不再抠图，联网与手动导入都保留背景。已有条目直接使用此前保存的原图，不需要重新下载或重新添加。卡片照片区统一为 205 点高，等比填充图框并裁去超出部分；详情和换照片预览可查看完整图片。详情中的「更换成品照片」可以导入自己的照片。联网失败或没有对应资料时，可重试或手动补充；已选照片和手动配方不会被后台刷新替换。

0.6.0 修正网站有图而应用提示没有成品图的问题：旧版将 `strCreativeCommonsConfirmed` 不是 `Yes` 的图片直接过滤，实际 Martini 返回 `No` 但有有效图片。新版按地址判断图片是否可用，继续保留来源和确认状态。重启新版后自动重试缺图条目，也可在详情点「联网补充配方与成品图」。

整体界面已改为像素风：奶油色纸面、薄荷绿侧栏、莓紫色操作按钮、阶梯切角和方块阴影；正文用 12 点中文像素字体，标题用 24 点。酒瓶贴纸和鸡尾酒原图保持真实照片。字体使用开源 [Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) 简体中文比例版，随应用嵌入且仅注册到应用进程，许可证随包保存；不需要安装系统字体。图标 v2 原图及内置生成工具提示词见 [图标记录](packaging/artwork/V2_PROMPTS.md)。

## 打开应用

直接打开本项目的 `build/Sipfolio.app`，点「新收藏」→「选择照片」→ 等待贴纸预览 → 填写酒名 →「加入收藏册」。快捷键 `⌘N` 新增收藏。

想减少手动录入：导入照片后点击「AI 识别并补充信息」→ 核对结果 →「采用并继续」→「加入收藏册」。已有收藏可以在详情页点击「AI 补充资料」。

AI 设置在主窗口右上角的滑杆按钮或「Sipfolio → 设置」（`⌘,`）中。密钥存入 macOS 钥匙串，可在设置中替换、移除或检查连接。

AI 使用 DeepSeek 官方 `deepseek-flash` 模型。点击识别时会将所选酒瓶图和已填写的酒名发送至 `https://api.deepseek.com`，按 DeepSeek 账户计费；缩小到最长边 1280 像素后发送。你的备注不进入请求。图片模糊或版本不明确时，结果会提示核对；生成的风味和鸡尾酒是建议，需要你确认。

生成鸡尾酒配方只发送喝法名称、关联酒瓶名称和类别，不发送图片、已有配方内容或个人备注。配方为一杯份量的参考建议，可按实际调配结果编辑。

应用要求 macOS 14 或更新版本。当前二进制为本机 Apple Silicon 构建，本地 ad-hoc 签名；尚未做公开分发、公证或商店发布。

## 开发与构建

只需 Xcode 和系统自带的 Make，不依赖第三方 Swift 包或 XcodeGen。

```sh
make build     # 编译 Debug 并生成 build/Sipfolio.app
make run       # 构建后打开应用
make test      # 运行核心测试与离屏界面渲染测试
make release   # 构建优化后的本地应用
make icon      # 从已选定的白底像素 PNG 生成 macOS 图标
```

可以在 Xcode 中打开 `Package.swift` 查看和编辑源码。终端生成的 `.app` 是常规使用入口。

项目源码同步到 [hyandnn/sip-portfolio](https://github.com/hyandnn/sip-portfolio)，`v0.6.0` 标记首个远程保存的功能版本。可在另一台 Mac 上恢复工程：

```sh
git clone https://github.com/hyandnn/sip-portfolio.git
cd sip-portfolio
make release
open build/Sipfolio.app
```

仓库包含源码、图标、字体及其许可证、测试与说明；构建缓存、开发测试输出、API 密钥和个人收藏数据库不上传。个人收藏的备份方式见下方「数据与照片」。应用源码沿用仓库中的 MIT 许可证，第三方字体与测试图片保留各自的许可和署名。

Makefile 在命令级指定 `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`，不修改系统的 Xcode 选择。Xcode 在其他路径时使用 `make build XCODE_DIR=/你的路径/Xcode.app/Contents/Developer`。

## 数据与照片

默认保存在 `~/Library/Application Support/Sipfolio/`，包含 `Sipfolio.store`、SQLite 辅助文件和 `Images/`。备份时退出应用，复制整个目录；更新或重新编译应用不删除收藏。

AI 资料保存在每款酒图片目录的 `knowledge.json`，与个人备注分开。0.3.0 为数据库加入可空的口味、年份和收藏日期覆盖值；旧条目沿用原来的日期，口味／年份初始为空。已通过旧版结构升级测试，照片与 AI 资料路径继续使用原条目 ID。

0.4.0 在同一 SwiftData 数据库新增 `CocktailRecipe` 条目，不改变酒瓶属性。已验证 0.2.0 和 0.3.0 结构的临时测试库升级，原酒瓶记录、口味、年份、日期、照片和 AI 资料继续可读。测试不会打开个人收藏库。

0.5.0 给配方实体新增可空来源关联 JSON 和参考链接，旧配方的单个酒瓶关联继续可读。鸡尾酒图片存入 `CocktailImages/<UUID>/`，包括原图、透明贴纸、缩略图与来源 `photo.json`；替换采用目录交换，保留失败前的图片。备份仍需复制整个 Sipfolio 数据目录。

0.5.1 沿用已有模型与图片目录，新鸡尾酒媒体的原图和兼容图片槽都保存带背景的照片，缩略图也由原图生成。旧贴纸文件保留，但蒙汗药界面显示原图；酒瓶图片流程继续生成贴纸。

导入照片最大 50 MB，校正方向并缩放到最长边 2400 像素保存；这里的「原图」指保留背景的导入照片，不是原文件的逐字节备份。缩略图最长边 420 像素，透明背景会保留。

每款酒是一个条目，酒名、口味和年份的重复检查忽略大小写和首尾空白。经典与佛手柑等版本可共用同一酒名，用独立口味字段区分。Vision 分离的是前景主体，复杂背景、遮挡或透明瓶身的效果需要用实际照片判断；失败时可以明确选择原图收藏。

开发测试可使用独立数据目录，避免混入个人收藏：

```sh
open -n build/Sipfolio.app --args --data-directory "$PWD/.local-data"
```

0.6.0 执行 7 项相关核心测试与 1 项离屏界面检查，验证 `No`／空确认字段下的有效图片、不安全地址拒绝、原图补充流程、持久化和旧配方兼容。检查两本收藏、空状态、导入、详情与编辑、AI 建议、换照片等预览，并增加 960×680 窗口布局。Release 应用已真实获取 Martini 配方、成品原图与缩略图；隔离启动检查确认打包字体与图标加载。未重复运行未改动的酒瓶 Vision 测试。

Dock 启动时显式使用普通应用策略并加载打包图标。开发检查通过隔离实例输出启动状态，不读取个人收藏；运行中的应用应显示图标，退出后若想常驻，可在 Dock 图标菜单选择「选项 → 保留在程序坞」。原生屏幕捕获限制仍存在，不能把启动状态检查当作 Dock 截图验收。

收藏墙、导入页和详情页通过 SwiftUI 离屏渲染检查。原生窗口捕获工具在本机返回捕获错误，实际文件选择、鼠标点击、拖放和导出的完整 UI 操作链尚未自动验收。受限执行环境也无法访问 Neural Engine；真实抠图测试已在本机正常权限下通过。
