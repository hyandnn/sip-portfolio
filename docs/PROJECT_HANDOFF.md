# Sipfolio 项目交接说明

整理日期：2026-10-07。来源：[用户提供的共享对话](https://chatgpt.com/share/6ac5ec2a-a768-83e8-80b4-bd654e5f0d94)。

本说明依据可见对话重建；原交接 ZIP 未成功下载。用户随后在本次对话中明确要求直接开始开发，已按以下 Mac V0 范围实施。

## 用户明确表达的目标

- 收藏自己喝过的酒，以真实酒瓶照片形成视觉记录。
- 自动抠图，把酒瓶做成小贴纸，放进收藏册。
- 支持多种酒类，避免被某个单一类别限制。
- 希望逐步加入简单介绍、风味以及适合制作的鸡尾酒。
- 名称采用 Sipfolio；视觉选择现代、活泼、多彩的图鉴与卡片收集感，灵感来自用户对宝可梦的喜爱。
- 用户已准备 Xcode，并希望开发过程可以在本机完成和验证。

## 对话最后的交接摘要记录

最后一条助手答复将首版范围归纳为：先开发 Mac 版，每款酒保存一个收藏条目，填写名称、类别和备注。该摘要还说明交接文件未写入本地。

具体配色、卡片边框与贴纸效果留待第一版运行后调整。卡片、稀有度、收藏进度等是设计灵感；对话没有给出完整规则，不应直接视为首版必须实现的功能。

## 建议的 V0 范围

下列内容是根据既有讨论整理的实施建议，具体细节可在开发中调整。

1. 从 Mac 导入照片，展示原图和处理状态。
2. 使用 Vision 尝试分离前景，生成透明酒瓶图片。
3. 预览贴纸，填写名称、类别和备注，再确认收藏。
4. 用 SwiftData 保存条目信息，用本地文件保存图片。
5. 在收藏墙展示条目，支持打开详情、编辑和删除。
6. 验证重启后的记录与图片仍可读取。

图片处理失败时应提供清楚的反馈和重试入口；具体原图回退与手动调整体验尚待实现时决定。前景检测可能同时包含杯子等物体，必须用真实照片验证，不能预先承诺准确识别酒瓶。

## 技术方向与边界

讨论建议使用 Swift、SwiftUI、Vision、Core Image、SwiftData 和少量 AppKit，优先采用 Apple 原生框架。模型与图像服务尽量独立于 Mac 界面，为以后 iOS 扩展留出空间。

首版优先建立本地收藏闭环。OCR、在线酒款识别、自动生成介绍、风味和鸡尾酒推荐作为后续阶段。云同步、账号、社交、商店发布与正式分发签名也属于后续工作。

XcodeGen 与 Makefile 在讨论中作为可重复构建方案提出；尚未选定实际工程方式。无需提前安装全部候选工具。最低系统版本和具体 API 可用性应在工程创建时查证。

## 建议开发顺序与验收

1. 建立可编译、可运行的 macOS 工程和基础界面。
2. 完成手动导入、信息填写、保存、查看与重启读取。
3. 加入前景抠图与贴纸预览，检查横竖图、透明背景和处理失败的体验。
4. 完善收藏墙与卡片表现，再进行真实照片的端到端验证。

最小验收场景：导入一张真实酒瓶照片 → 查看处理结果 → 输入名称、类别、备注 → 保存 → 从收藏墙打开 → 重启后再次打开。还需验证取消操作、损坏图片、空名称和文件保存失败时的行为。

## 本次开发结果

Mac V0 已实现导入／拖放、Vision 自动抠图、多主体选择、透明白描边贴纸、原图回退、名称／类别／备注、SwiftData 持久化、收藏墙、分类搜索排序、详情编辑删除与 PNG 导出。

用户随后明确要求使用 DeepSeek API，并提供了用于接入的密钥。0.2.0 已加入 DeepSeek Flash 图片识别、结果确认页、名称／类别建议、简介／风味／鸡尾酒资料，以及已有收藏的 AI 补充入口。密钥只保存在 macOS 钥匙串，不应写入任何交接文档或源文件。

已用公开测试照片完成真实 API 调用。识别需要用户点击，会发送所选酒瓶图及酒名，个人备注不发送；结果由用户确认后保存。AI 资料作为每个条目的 `knowledge.json` 保存，不修改既有 SwiftData 模型。

应用位于 `build/Sipfolio.app`；正常使用的收藏保存在 `~/Library/Application Support/Sipfolio/`。没有将公开测试照片预置到用户收藏中。

0.3.0 按用户追加需求新增独立的手动口味、年份及可调收藏日期。重复规则使用酒名＋口味＋年份；卡片在类别后显示 AI 风味标签。口味是版本特点，风味是品鉴描述，两者不混用。旧条目口味／年份为空，收藏日期回退到原来的添加时间；旧结构升级测试已通过。

用户希望最后再讨论像素风界面与图标，本轮未实施视觉风格重做。可在功能稳定后讨论像素界面保留真实贴纸，或整套界面和酒瓶一起像素化。

已完成核心自动化测试、真实照片抠图测试与离屏界面渲染。原生窗口捕获工具报错，因此文件选择／鼠标／拖放／导出的完整 UI 操作尚未自动验收。构建、使用、存储说明和预览见 `README.md`。

0.4.0 用户明确要求先做图标、界面风格后改。已通过内置 image_gen 生成可爱像素酒瓶笑脸，并按追加指令把紫底改为白底，直接接入应用图标。源 PNG 和提示词保存在 `packaging/artwork/`。

类别改为自由输入与已有收藏类别提示，同时移除 DeepSeek 解码中的固定类别映射；蜂蜜酒等类别可完整保存，侧栏仅显示实际收藏的类别。

新增鸡尾酒集：从酒瓶详情推荐喝法创建可编辑配方，也可独立新建；记录材料用量、步骤、杯型、装饰和备注。DeepSeek 可按名称生成配方建议，由用户核对保存。配方存入新增的 SwiftData `CocktailRecipe` 实体，关联酒瓶用可空 UUID 和创建时的名称，删除酒瓶不级联删除配方。24 项自动化测试通过；旧版升级使用临时测试库，不接触个人收藏。

0.5.0 用户确认卡片问题是高度／边框尺寸不齐，已固定信息槽高度；排序不再嵌套 Picker 子菜单。用户选定「藏酒册＋蒙汗药」，已用于导航和配方页。

保存酒瓶时默认把已确认的 AI 推荐喝法一起收录（可取消），保留手动添加方式；同名中英文常见喝法去重，记录多瓶关联且不覆盖原配方。已有酒瓶可通过「收录酒瓶推荐」批量补录。

TheCocktailDB 官方公开接口按喝法名称获取匹配的配方和 Creative Commons 已确认图片，保存来源，Vision 本地生成成品贴纸；未匹配时留待补充，抠图失败标记原图，可调整主体或换自己的照片。后台只填空白，保护手动内容／照片与在请求期间的重命名／删除。

配方模型新增可空 `sourcesJSON`／参考链接，旧版单关联回退兼容。鸡尾酒图片单独保存在 `CocktailImages`。30 项自动化测试通过，覆盖 0.4.0 升级与真实鸡尾酒抠图。Dock 启动显式设为 regular 并加载 ICNS；使用隔离启动实例核查策略和资源，原生屏幕／鼠标验收仍受捕获故障限制。

藏酒册改名为「藏酒屋」。两个收藏页主区域顶部删除重复中文标题，只保留英文与 slogan；侧栏继续提供入口和类别选择。排序菜单只显示纯文字选项，不显示选中对号。界面整体像素风仍等待用户后续讨论。
